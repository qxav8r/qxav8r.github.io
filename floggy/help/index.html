Quick Start — Your First Month

New to Floggy? This gets you from a blank data file to your first logged flights. Full detail on every step lives in the numbered sections below — come back to them as needed.

  1. In eCrew, pull your Crew Schedule for the month: eCrew → Schedule → My Schedule → Print → press the file/export icon → Save as Text (.csv).
  2. In Floggy's Collect workspace, press Parse Schedule and select that file.
  3. Open the Flt Data workspace — your flights and duty events should now be listed.
  4. For each trip, open its Pairing Details in eCrew (eCrew → Crew Schedule → My Schedule → select a pairing → Pairing Details) and save the page — CMD-S in Safari for a WebArchive, or the complete-page save option in Chrome/Firefox.
  5. Back in Collect, press Parse (Archive or HTML) and select that saved file. Repeat for each pairing.
  6. After you've flown the trips, pull your Pilot Logbook report (eCrew → Reports → Pilot Logbook Report → Save as Text (.csv)) and press Parse LogBook in Collect. Run it last — it is the legal record for landings, PIC/SIC capacity, instructor time and Part 121/91 (see Section 8, Recommended Order).
  7. Select your flights in Flt Data and press LogTen Export to send them to LogTen Pro.
Start with a single month before processing a larger date range or your full history. Once you're comfortable, see Section 13, Common Workflows, for ongoing use and building a full historical logbook.

Section 1 — Overview

Floggy is a macOS utility application developed by Bill Bowling, a pilot based in Portland, Oregon (PDX). Floggy collects and normalizes scheduling data from eCrew and centralizes it for export into electronic logbooks, calendars, and related flight tracking tools.

Think of Floggy as a translator. Your airline's scheduling system (eCrew) stores your flights one way; LogTen Pro expects them in a different format. Floggy reads the eCrew pages you save from your browser, cleans up the data, and delivers it to LogTen in a format it understands — so you are not manually typing flight numbers, times, crew names, duty periods, and related details by hand.

In addition to LogTen export, Floggy supports:

  • Calendar generation using ICS files
  • Apple Calendar integration using AppleScript
  • Basic rig calculations
  • CSV exports for review, backup, or use in spreadsheet applications

Floggy is intended for pilots who maintain electronic logbooks and want a lightweight, focused workflow for transforming raw scheduling and duty data into accurate logbook entries while reducing repetitive manual data entry.

This guide is version 2.6. It is formatted as an HTML document and can be opened directly in any web browser, or via the Help button in Floggy, which saves a copy named FloggyHelp.html to your Desktop (replacing any earlier copy) and opens it in your default browser. Curious what changed recently? See the Release Notes at the end of this guide.
This documentation assumes basic familiarity with eCrew and standard macOS operations such as file saving, Finder navigation, and copy/paste.

Section 2 — About Data Collection

Floggy uses multiple data sources as input to improve accuracy and detail. No single source provides complete information — combining sources produces the most complete logbook entries.

Primary Source — eCrew Schedule File

The schedule file is one of two primary sources for Floggy. It is generated from the Print function within eCrew and saved as a .csv file. To access it:

eCrew → Schedule → My Schedule → Print

To save the schedule report:

  • Press the file/export icon in the print window
  • Choose Save as Text (.csv)

This provides your monthly schedule structure, pairing numbers, and assignment overview.

Primary Source — Pairing Details WebArchive (or Saved HTML Page)

The Pairing Details page is the other primary source and captures leg-by-leg detail that the schedule file does not include. To access the Pairing Details window:

eCrew → Crew Schedule → My Schedule
  → select a pairing
  → press Pairing Details at the top of the trip details window

Once the Pairing Details window is displayed, save it using whichever browser you have it open in. All three browsers below capture the same underlying data — leg-by-leg times, aircraft type, tail number, crew names, FDP, and duty times — and Floggy's Parse (Archive or HTML) button reads all three the same way (see Section 8 for the button itself).

This page carries more than just the pairing you're viewing. Save it while you're working within your current bid month, and it also captures a plethora of background data behind the scenes — Dashboard, Crew Data, and Training Events — which Floggy extracts alongside the pairing itself. Save it for a pairing from a different bid month, though, and that background data still reflects your current month, not the pairing's — stale and mismatched, not useful. In that case, only the pairing details themselves are meaningful; turn on Bypass Dashboard (Section 8) to skip the rest.

Safari — single WebArchive file

Use CMD-S in Safari to save a WebArchive. This produces one self-contained .webarchive file — nothing else to keep track of.

Safari's Cmd-S save panel lets you name the file and browse to any folder — save your WebArchive files to the same folder every time (Desktop works well) so they're easy to find and drag into Floggy right after saving.

Chrome or Firefox — saved HTML page + companion folder

Use CMD-S and choose the complete/full-page save option — "Webpage, Complete" in Chrome, "Web Page, complete" in Firefox. Unlike Safari, this produces two items together in the folder you save to: a main .html file (e.g. eCrew.html) and a same-named companion folder (e.g. eCrew_files) holding the rest of the page's pieces. Both are needed — don't move, rename, or delete one without the other.

eCrew.html            ← the file you select in Floggy
  eCrew_files/          ← its companion folder, must stay alongside it
    CrewSchedule.html
    Index.html
    Main.html
    ... (Firefox may nest these a level or two deeper —
         Floggy finds them either way)
You only ever select the .html file itself in Floggy — never the companion folder. Floggy automatically locates and reads the companion folder for you, including files Firefox nests in subfolders. Just make sure the folder stays in the same location as the .html file, exactly as the browser saved it.
Why use Chrome or Firefox instead of Safari? Safari is preferred for many reasons, including that you can save the page on an iPad or iPhone and mail a copy to your desktop if needed — that's the workflow the WebArchive path was built around. The Chrome/Firefox pipeline exists for users who simply prefer another browser, and it's also a good option on older Macs, since Chrome and Firefox keep releasing updates for older hardware well after Safari itself stops being updated there. Just remember that a modern version of LogTen Pro won't run on an older OS — but if you have an older OS paired with an older version of LogTen Pro, you're in luck, because Floggy will still feed it either way. Floggy aims to be flexible.

Managing Saved Files

Schedule files saved via the Print function will be named sequentially:

ScheduleReport.csv
ScheduleReport-1.csv
ScheduleReport-2.csv
... and so on

You don't need to manage these yourself — once Parse Schedule finishes successfully, it moves the file you selected into your Documents folder and renames it with your last name, crew ID and the report's own date range (see Section 8, Parse Schedule). Parse LogBook does the same with logbook reports. That clears the plain ScheduleReport.csv name out of the save location each time, so your next Print/Save from eCrew should default back to that plain name rather than continuing to increment.

Pairing Details files (WebArchive or saved HTML) are handled differently — Parse (Archive or HTML) copies the data it extracts into a compact .flog archive in your Documents folder, but leaves the original file (or file-plus-folder pair) exactly where you saved it. Nothing moves or renames it for you; see Section 8, Parse (Archive or HTML), for when it's safe to delete.

WebArchive files saved from the Pairing Details window will default to the filename eCrew.webarchive. If a file with that name already exists on the Desktop, Safari will prompt you to replace it. You may allow the replacement to keep a single current file, or choose a different name to preserve multiple snapshots — for example when capturing several pairings before parsing, or when saving a copy for pay dispute reference.

This overwrite prompt comes from Safari and applies only to source files you save before parsing (WebArchive, Schedule, Logbook exports). Floggy's own data file — your .flgy file — has separate overwrite protection built in; see Release Notes, Data File Safety Improvements.

Chrome and Firefox saves follow the same idea but default to eCrew.html plus an eCrew_files companion folder. If a save with that name already exists in the destination folder, your browser will either prompt to replace it or append a number to the new copy's name (e.g. eCrew(1).html / eCrew(1)_files) — either way, keep each .html file paired with its own matching folder if you're preserving multiple snapshots.

Once Parse (Archive or HTML) has run on a file, its compact .flog archive (see Release Notes, Compact Archive Files) already preserves everything needed to reconstruct that parse. The original capture — the much larger .webarchive file, or the .html file and its companion folder — is no longer needed for Floggy's own purposes at that point and can be deleted if you're managing disk space — the same keep-or-delete choice described above for schedule reports applies here too.

The .flog archive files themselves exist purely for your reuse or as a simple archive of past parses. Floggy does not manage or clean these up automatically — you're free to manually delete or move them at any time.

All of Floggy's archived files share one naming pattern, so they sort together by type and date in a Finder window:

WILCO-1234_Schedule_2026-07-01_to_2026-07-31.csv
WILCO-1234_Logbook_2026-08-01_to_2026-08-31.csv
WILCO-1234_Pairing_2026-09-15_4150.flog
WILCO_Flighty_2026-01-01_to_2026-12-31.csv

That is your last name and crew ID, the file type, then the report's start and end dates (or, for a pairing, its start date and pairing number). A Flighty export carries no crew ID, so its name has none, and its dates are the calendar year you imported. If an identical file is already in Documents, Floggy skips the archive step and leaves your source file where it is. If a different file already has that name, Floggy asks: Cancel, Replace, or Keep Both (which saves the new one with -2, -3… added to the name).

Legal Record — Pilot Logbook Report

The Pilot Logbook Report is eCrew's record of what you actually flew. It is saved as a .csv file. To access it:

eCrew → Reports → Pilot Logbook Report

To save the logbook report:

  • Press the file/export icon in the report window
  • Choose Save as Text (.csv)

This report is the legal record of what you flew, and Floggy treats it as the final word for:

  • Out and in times, block time and tail number for each flown leg
  • PIC / SIC capacity — including PIC from the right seat as an instructor, or SIC while listed as captain
  • Who landed each leg, and instructor time
  • Part 121 vs Part 91 time classification

It can cover many months or years in one pull, so it is the backbone of a historical logbook. It does not include crew other than the captain, duty or FDP times, trip numbers, or non-flying duties — those come from the schedule and Pairing Details.

The logbook report shows all times in your base time, while every other eCrew report uses local station time. Parse LogBook converts them for you — see Section 8, Parse LogBook. Pull one report per base: if you changed bases, request a separate report for the dates at each base.
Floggy parses saved snapshots exactly as captured at the time of saving. If sections of the page are collapsed, filtered, or partially loaded when saved, those sections will not be available during parsing. Always ensure the page is fully loaded and expanded before saving.

Secondary Source — Alaska Flight Status (Flifo)

The Flifo button (Flt Data workspace, Section 9) is a secondary source for quick updates. It looks up the selected flights on Alaska Airlines' public flight status page and fills in actual out/in times and the tail number — handy for keeping the current trip up to date between eCrew captures.

  • Limited look-back, limited look-ahead. Alaska's flight status only reaches about 3 days back and 3 days ahead. Flights outside that window are skipped.
  • Not a replacement for eCrew. Your eCrew schedule, Pairing Details, and Pilot Logbook remain the primary sources for complete records. Flifo only touches actual out time (ATD), actual in time (ATA), and tail number.
  • Scheduled times are never changed. Contract (CBA) scheduled times from eCrew differ from Alaska's public schedule by design, so Flifo leaves STD and STA alone.
  • Before the flight: only the planned tail is filled in; departure and arrival times are still estimates and are not used.
Typical use: set up your trip at home from eCrew as usual, then run Flifo during or right after each day's flying to pick up actual times and aircraft swaps — and export to LogTen as you go.

Section 3 — System Requirements

Operating System

macOS compatible with the current version of LogTen Pro in use.

Hardware

  • Intel-based Mac: supported via legacy LiveCode standalone builds
  • Apple Silicon (ARM64 / M-series): supported via HyperXtalk-based builds

Required Applications

  • Safari (preferred browser — see note below), or Chrome or Firefox as an alternative
Safari is the recommended browser and is the only one that produces a single WebArchive file. Chrome and Firefox are fully supported alternatives via a saved HTML page — see Section 8, Parse (Archive or HTML), for the full explanation and usage steps for each browser.

Suggested Applications

  • LogTen Pro — not required to run Floggy, but nearly everything Floggy does is aimed at feeding it, so you'll want it installed before long.

Optional Applications

  • Apple Calendar (for calendar integration)
  • Flighty (alternate data source) — particularly useful for capturing tail number and aircraft type for deadhead legs, as eCrew does not provide this information for deadheads. Flighty also often captures more accurate actual departure and arrival times than eCrew.

Storage

Floggy data files (.flgy) may be stored in any location of your choice — see Section 5, Data File Storage, for recommended locations and an important note on iCloud Drive sync latency.

Runtime Requirements (Stack File Users Only)

Running Floggy as a stack file instead of a standalone app requires a LiveCode or HyperXtalk runtime — see Section 5, Stack File (Alternative), for download links and setup.

Section 4 — Before You Start

Getting Started

A few things worth thinking about before your first launch:

  • Floggy can live anywhere on your Mac — there's no install location requirement. The Applications folder is a natural, common-sense choice if you don't have another preference.
  • LogTen Pro isn't required just to run Floggy, but nearly everything Floggy does is aimed at feeding it — you'll likely want it installed before long.
  • Have Safari available for saving eCrew pages — recommended, but Chrome or Firefox work too (see Section 3)
  • Decide where your Floggy data file will be stored
  • Allow extra time during first launch for macOS permission dialogs
  • If you plan to use Add Calendar (Cal – APS), turn on Calendar's Time Zone Support and set it to your home base — see Section 10, Cal – APS, for details

Safari Save Location

WebArchive files are saved via Safari's Cmd-S save panel, which lets you name the file and browse to any folder. Pick one folder — Desktop works well — and save there every time, so saved files are always easy to find and drag into Floggy right after saving.

Permissions

Because Floggy interacts with Safari, LogTen Pro, Apple Calendar, and local files, macOS will request permissions during first launch. This is normal. You may see prompts for:

  • Automation
  • Files and Folders
  • Calendars

Click Allow or OK for each prompt.

If you accidentally clicked Don't Allow, you can re-enable permissions at any time:

System Settings → Privacy & Security
  → select the relevant category
  → enable Floggy (or HyperXtalk / LiveCode if running as a stack file)

If macOS blocks Floggy from opening:

System Settings → Privacy & Security → Open Anyway

This only needs to be done once.

Apple Silicon / Code Signing Note

If you are running an older Intel-based build of Floggy on an Apple Silicon Mac, macOS may prompt you to install Rosetta. Follow the on-screen prompt to install it. This only needs to be done once.

For users who encounter persistent permission or code signing issues with the standalone build, a SignAndAuthorize AppleScript utility is available upon request. This script automates the following steps:

  • Clears macOS quarantine attributes
  • Fixes application permissions
  • Resets system privacy (TCC) permissions for the app
  • Applies an ad-hoc code signature
  • Verifies the signature and logs the result to the Desktop

Once complete, launch Floggy and approve the Calendar access dialog when it appears. That permission will persist for future launches. A signing log is saved to the Desktop for reference. To request the SignAndAuthorize utility, contact the developer.

Quitting Floggy & the First-Launch Quit Menu

Closing Floggy's main window with its red close button quits the app: Floggy saves your data file, writes a backup to your Desktop (see Section 5), closes its palette windows (Workspaces, Display Flts, Display Events, Sort) and exits — no force quit needed.

The very first time you launch a freshly built standalone copy, the Quit menu item may appear dimmed. This happens only occasionally, and only on that first launch. Use the red close button instead — Quit behaves normally on every launch after that.

Gatekeeper & Permissions — Your Options

macOS Gatekeeper and the privacy permission system (TCC) can present challenges when running unsigned applications like Floggy. The following options are available, from least to most friction:

Option 1 — Run as a Stack File in the IDE (Recommended)

Running Floggy as a stack file inside the LiveCode Community or HyperXtalk IDE is the smoothest long-term experience. Once the runtime is installed and macOS permissions are satisfied for the IDE itself, Gatekeeper and TCC issues are largely bypassed on an ongoing basis. See Section 5, Stack File (Alternative), for runtime download links and setup steps.

Option 2 — Standalone Build + SignAndAuthorize Utility

For users who prefer a standalone application, the SignAndAuthorize AppleScript utility is available upon request. It performs a one-time automated fix that clears quarantine attributes, resets TCC permissions, and applies an ad-hoc code signature.

Option 3 — Standalone Build + Manual Open Anyway

If Gatekeeper blocks Floggy from opening (step-by-step with pictures in the Gatekeeper guide):

System Settings → Privacy & Security → Open Anyway

You may also need to manually enable permissions under:

System Settings → Privacy & Security → Automation
System Settings → Privacy & Security → Files and Folders
System Settings → Privacy & Security → Calendars
Regardless of which option you choose, once Gatekeeper and TCC permissions are satisfied, day-to-day use of Floggy is straightforward. The friction is front-loaded to first launch only.

Section 5 — Installation

Standalone Application

Download the build for your Mac from the Floggy page (Apple Silicon or Intel), double-click the .zip to unzip it, and copy Floggy to your Applications folder or another location of your choice. Floggy does not use an installer. Floggy stores all user-generated data externally in a separate .flgy data file that you control. The application itself is read-only with respect to your source data.

On first launch, macOS may require you to explicitly allow the application to run. See Section 4 — Gatekeeper & Permissions for your options.

Stack File (Alternative)

Stack files are available upon request and may be preferable for users who wish to avoid macOS Gatekeeper restrictions or prefer a more seamless data handling experience — because the stack operates directly within the runtime environment, data is handled internally and doesn't require the external .flgy file management the standalone build uses.

Stack file operation requires one of the following runtimes:

  • LiveCode Community Edition 9.6.3 — archive.org download
  • HyperXtalk (Apple Silicon supported) — hyperxtalk.com download

To install:

  • Download and install your preferred runtime
  • Request the Floggy stack file from the developer
  • Open the stack file directly in the runtime

First Launch — Data File Setup

Floggy requires a data file (.flgy) to store your flights, crew records, and preferences. On first launch you will need to either create a new data file or open an existing one.

To create a new data file:

  • In the Data workspace, press Export User Data
  • Choose a filename and location
  • Press Save

To open an existing data file:

  • In the Data workspace, press Import User Data
  • Navigate to your existing .flgy file
  • Press Open
After creating a new data file, verify two critical fields in the Data workspace before relying on parsed data:

eCrew Name — Your name exactly as it appears in eCrew, last name first. This is populated automatically on your first parse. Verify it matches precisely — Floggy uses this for parsing logic and data management throughout the application.

eCrew Base — Your home base airport code (e.g., PDX). Also auto-populated on first parse. Floggy uses this for timezone calculations and calendar event placement.

To manually edit either field: CMD-Click to unlock, make your change, CMD-Click again to lock.
Incorrect or missing values in these fields will affect parsing accuracy across all data sources.

Floggy automatically saves data at meaningful checkpoints — after a parse (Parse Schedule, Parse (Archive or HTML), Parse LogBook, Parse Flighty); after Copy Crew Names, Delete Flights, Unlock/Lock Flights, CSV Export, or a Flifo merge; after using the File Path For User Data control; and when the application closes. Switching workspaces or changing the theme does not trigger a save on its own, since neither changes your underlying data.

If you have been working for a while without parsing anything new, it's good practice to close and reopen Floggy (or use Export User Data) before assuming your latest edits are safely on disk.

Automatic Backup on Close

Each time Floggy closes, it first writes a backup copy of your data to the Desktop, named with your first initial and last name plus the date — for example rwilco_Backup_2026-10-29.flgy. A second backup on the same day is saved as rwilco_Backup_2026-10-29-2.flgy (then -3, and so on), so an earlier backup is never replaced. Delete or archive old backups whenever you like; Import User Data can load any of them.

If a save or backup can't be written (a locked file, or a folder that isn't available), Floggy shows a Save Failed dialog with the reason. Your data is still loaded — fix the problem, or use Export User Data to save somewhere else.

Data File Storage

Your data file may be stored in any location. Common locations:

iCloud Drive (recommended for multiple Mac users)
  iCloud Drive / Floggy / MyData.flgy

Desktop (simple single Mac setup)
  ~/Desktop / MyData.flgy
iCloud Drive sync introduces latency. During an active data-collection session — running multiple parses back to back in the Collect workspace — keep the data file on local disk rather than iCloud Drive, then move or re-save it to iCloud Drive once the session is done. Working directly against a syncing iCloud file while parsing repeatedly can lag or produce stale reads mid-session.
Floggy supports multiple data files. This can be useful when managing large logbooks across multiple years. For example: 2023 Floggy Wilco.flgy, 2024 Floggy Wilco.flgy, 2025 Floggy Wilco.flgy. Use Import User Data and Export User Data in the Data workspace to switch between files as needed. Leading with the year (YYYY) puts your files in chronological order automatically when sorting by name in a Finder window — no need to sort by date modified.
Performance may decrease as the flight data set grows larger. Floggy performs internal auditing on flight data, and larger datasets will increase processing time. Splitting data across multiple files by year is a practical way to maintain performance.
Parse (Archive or HTML), Parse Schedule and Parse LogBook all file their source material away automatically after a successful parse — a compact .flog record for each pairing, and a renamed copy of each schedule or logbook report (see Section 2, Managing Saved Files). All of them land in your Documents folder, independent of where your data file itself is stored.

Section 6 — User Interface Overview

Floggy is organized into six distinct workspaces. Each workspace is dedicated to a specific function. All workspaces share a common layout:

Common Layout

Upper Panel

The main data display area. Contents vary by workspace but generally display raw parsed data, flight records, or reference tables. You do not need to edit this panel directly in most workspaces.

Lower Panel

Displays status messages, parse results, warnings, and errors. Always check the lower panel after any operation. It confirms whether an action succeeded and flags anything that needs attention.

Button Bar

A row of action buttons along the bottom of the screen. Buttons are specific to each workspace. Many buttons operate only on selected rows in the data panel — always confirm your selection before pressing an action button.

Title Bar

The window's title bar shows the Floggy version and the workspace you're in — for example Floggy 2.6 Arm — Flt Data. Dialogs are titled with the workspace or button they belong to (Parse Schedule, Cal – APS, LogTen Export, and so on), so you can always tell where a message came from.

Work Space Indicator (lower-right corner)

Displays the name of the current workspace. Click it to open a popup menu listing all workspaces. The menu also includes Nav Tool, which opens the floating Workspaces palette for persistent one-click navigation. See Section 7 for details.

Available Workspaces

  • Collect — Import and parse source data (formerly Home / Import)
  • Flt Data — Manage flight records and exports
  • Cal – ICS — Generate ICS calendar files
  • Cal – APS — Write events directly to Apple Calendar via AppleScript
  • Data — Reference databases and user settings
  • Settings — Font, theme, and button style preferences

General Tips

  • Many buttons operate only on selected rows. Click to select a single row, Shift-Click for a range.
  • CMD-Click is used throughout Floggy to unlock fields for editing and to access additional functions on certain buttons.
  • Always check the lower panel after every operation.
  • Floggy saves automatically whenever your flight data changes. Switching workspaces or changing the theme does not save on its own (see Section 5).
Selecting one or more rows in Flt Data (Section 9) is how you tell many buttons what to work on — and that selection carries across workspaces, not just within Flt Data. Buttons that depend on it: Copy Crew Names, Delete Flights, LogTen Export, HTML Export, CSV Export, Display Flts, and Flifo all act on whatever is currently selected in the Flt Data panel. Build ICS Data (Cal – ICS, Section 10) and Build Events (Cal – APS, Section 10) do too, even though you press them from a different workspace — make your selection in Flt Data first, then switch workspaces to build. Sort Flights and Unlock Flights are the exceptions: both work on the entire list and ignore selection.

Section 7 — Navigator & Keyboard Shortcuts

Work Space Indicator & Popup Menu

The Work Space indicator in the lower-right corner of every screen displays the name of the current workspace. Clicking it opens a popup menu listing all workspaces: Collect, Flt Data, Cal – ICS, Cal – APS, Data, Settings. Click any name to jump directly to that workspace. The menu also includes a Nav Tool item at the bottom.

Nav Tool — Workspaces Palette

Selecting Nav Tool from the Work Space popup menu opens the Workspaces palette — a small floating window listing all six workspaces. The palette stays visible while you work and can be positioned anywhere on screen. Click any workspace name to switch immediately. It is themed automatically with the active color theme.

Below a separator line, the palette also has a Display Flts button. It opens (or refreshes) the Display Flts data window — the same as the Display Flts button in Flt Data (Section 9) — without leaving the workspace you're in. It shows the flights selected in Flt Data, or all flights if none are selected.

This makes the handy Display Flts window available while you work in the Collect workspace: open it from the palette, then parse your schedule and pairings and watch the rows fill in — no trips back and forth to Flt Data.
The Workspaces palette is also useful when moving between Collect and Flt Data repeatedly during a parsing session — for example, parsing a pairing, checking results in Flt Data, then returning to Collect for the next pairing.

Section 8 — Collect Workspace

The Collect workspace is the starting point for all data imports. All raw eCrew data comes in through this screen before it becomes usable flight data. Floggy will open to the workspace that was active when it was last closed, so the Collect workspace may not always be the first screen displayed.

Data Panel (upper panel)

Displays the raw content of the file you just parsed — the imported data pulled directly from your saved eCrew file or WebArchive. Think of it as a staging area. You do not need to edit or interact with this panel directly. If it displays a large block of data after a parse, that is normal.

Output Panel (lower panel)

Displays status messages and results after each button press. After a successful parse you will see a summary — number of flights detected, date ranges, and any warnings. Errors also appear here.

Always check the Output panel after every parse. It tells you whether the import worked and flags anything that needs attention.

Buttons

Parse (Archive or HTML)

Imports a Pairing Details page saved from eCrew. This and Parse Schedule are the two primary data sources for Floggy — together they capture the most complete picture of your trips. The saved page contains three sections that this button reads: Pairing Details (leg-by-leg times, aircraft type, tail number, FDP, and duty times), Dashboard, and Crew Data.

This single button accepts three kinds of saved input, so you can use whichever browser you prefer:

  • Safari WebArchive (.webarchive) — a single self-contained file, saved with CMD-S in Safari.
  • Chrome or Firefox HTML page (.html) — saved with "Save Page As" / "Save Page" using the complete/full-page option, which produces a main .html file plus a companion "..._files" folder alongside it. Select the .html file itself; Floggy automatically locates and reads the companion folder for you, including files nested in subfolders (Firefox nests its saved fragments more deeply than Chrome, but both are handled the same way).
  • Compact archive (.flog) — a previously written compact archive (see Release Notes, Compact Archive Files) can be selected here to re-run a pairing without needing the original capture at all.
Dashboard, Crew Data, and Training Events on a saved Pairing Details page always reflect your current bid month, regardless of which month's pairing you are actually viewing. Parse LogBook

Imports your eCrew Pilot Logbook report — the legal record of what you flew. It fills in out/in times, tail number, block time, PIC/SIC capacity, landings, instructor time and Part 121 vs Part 91 for every leg in the report, and it can cover any date range in one pull. The logbook report is saved as a .csv file.

Base Time Conversion

The logbook report lists every time in your base time; every other eCrew report uses the local time at each station. Parse LogBook converts each leg from base time to the departure and arrival stations' local times, using the Airport Data table (including daylight saving time), so its times line up with the rest of your data. Before it starts, a Logbook Times notice shows the base from the report header and the report's date range.

The conversion uses one base for the whole report. If you changed bases during the period, Cancel at the Logbook Times notice and pull a separate report for the dates at each base.
Scheduled or Actual?

The report's "Generated on" line (at the bottom of the file) tells Floggy when it was run. A leg with a tail number that arrived before that time is treated as flown, and its times go into the actual (out/in) fields. Legs still in the future go into the scheduled fields.

Deadheads

A leg with no block time and no PIC or co-pilot time is recorded as a deadhead.

When the Flight Is Already in Flt Data
  • Times, tail, block, landings, instructor and Part 121/91 from the logbook replace what's there — the most recent import wins, the same as every other parser.
  • PIC / SIC capacity is always taken from the logbook, even if that clears a capacity another parser set.
  • Captain's name: if one name contains the other (for example "COMLEY" and "COMLEY Justin"), the fuller name is kept; otherwise the logbook's name is used.
  • A leg already recorded as a deadhead stays a deadhead.

The Data panel shows a TIME CONVERSION summary (actual and scheduled leg counts, plus any leg whose times don't match its block time or couldn't be converted) and, when it changed anything on existing flights, a short LOGBOOK MERGE list of what it changed.

Calculate Rig

Recommended Order

Every parser updates the flights already in Flt Data, and the most recent import wins for the fields it supplies. Run them in this order so each source ends up owning the fields it's best at:

  1. Parse Schedule — lays down every duty for the month, with crew names and duty times.
  2. Parse (Archive or HTML) for each trip — adds scheduled times, tail numbers, block, trip numbers and FDP, and corrects crew.
  3. Parse LogBook, once the trips are flown — the final word on out/in times, capacity, landings, instructor time, block and Part 121/91.
Building a historical logbook? Parse Schedule plus Parse LogBook covers what most pilots need, and the logbook report can span years in one pull. Add Parse (Archive or HTML) only if you want scheduled times, trip numbers or FDP times in your logbook — it means saving one page per trip.

Known Edge Cases

Crew change in the middle of a duty day

If your crew changes partway through a duty day (for example, a training captain leaves after the first leg), Parse Schedule can assign the later crew to the earlier leg. Running the recommended order — Parse Schedule, then Parse (Archive or HTML), then Parse LogBook — corrects the captain's name and your capacity (PIC/SIC time) on that leg, because the logbook is the record for both. The SIC name on that one leg may still be wrong.

Fix: correct the SIC name for that flight in LogTen Pro after import.

Airport Data

Reference database of airports by IATA code, each with its standard UTC offset and a list of upcoming DST transition dates (spring-forward and fall-back pairs, several years out). Powers DST-aware timezone conversion in calendar exports — Floggy uses the offset together with the surrounding transition dates to determine whether a given flight or duty time falls in daylight or standard time at that airport.

Duty Codes

Maps eCrew duty type codes to plain-language descriptions. For example: G,LB = Line Building; G,IB = IBT Union Business. Determines how records are categorized in the Flt Data workspace.

Each row is three comma-separated items: the first is a flight/duty type category — G Ground, F Flight, R Reserve, S Simulator, or X to exclude the code from categorization; the second is the exact code as it appears in eCrew; the third is a plain-language description, which can simply be copied from eCrew. New duty codes occasionally appear in eCrew — add a row here for any code you don't recognize.
Both Airport Data and Duty Codes carry an internal version tag on their first line. When importing a data file via Import User Data, Floggy checks this tag and skips loading that field if the incoming copy predates the version currently required — protecting corrected reference data already in your stack from being silently overwritten by an older import.

eCrew Pilot Logbook Data

Stores tail-number data gathered by Parse LogBook. May be empty if Parse LogBook has not been run.

Crew Data

Links crew members to specific flights by date, route, and seat position. Populates PIC, SIC, FA, and FA2 fields. Used by Copy Crew Names in the Flt Data workspace.

Crew Data is populated automatically by the various parsing functions. When parsing a WebArchive, Floggy captures crew assignments embedded in the eCrew pairing data. This data is retained and reused when merging subsequent imports and during internal audit runs, ensuring crew associations remain consistent across your dataset.

Crew Names

Roster of crew members with LogTen People IDs, airline, and last-seen date. Supports clean crew associations in LogTen export.

Section 13 — Common Workflows

This section describes the most common usage patterns for Floggy. New users should start with the Beginner workflow and progress to the Ongoing workflow once comfortable with the process.

Beginner — First Month

See Quick Start at the top of this guide for the step-by-step first-month walkthrough. Once you've successfully processed one month, processing multiple months at once is straightforward — the workflows below cover ongoing use and building a full historical logbook.

Ongoing Users

For pilots maintaining an active logbook with Floggy:

  1. Before a trip, preload flights into LogTen using Parse Schedule and LogTen Export.
  2. During the trip, log times, approaches, and landings per leg in LogTen Pro.
  3. After trip completion, save the Pairing Details WebArchive and run Parse (Archive or HTML) to update flight data with actual times, FDP, and duty periods.
  4. Run Parse LogBook for the period you've flown — it sets landings, capacity, instructor time and Part 121/91 from the legal record.
  5. Re-export to LogTen to capture updated times.
  6. Run Calculate Rig and compare results against RainMaker or your airline's pay system.

New Users — Building a Full Logbook

For pilots building a complete historical logbook, work forward one month at a time until you're comfortable with the process, then switch to processing a year at a time:

  1. Load schedule data using Parse Schedule (.csv).
  2. Optional: add pairing data using Parse (Archive or HTML) for each pairing — only needed if you want scheduled times, trip numbers or FDP times (see Section 8, Recommended Order).
  3. Load eCrew logbook data using Parse LogBook (.csv) last. One report can cover a year or more — pull separate reports for each base if you changed bases.
  4. Audit: use Sort Flights to sort Flt Data by Flt Type, then review crews and trip numbers together. Trip numbers and complement can help you make an educated guess at crew assignments where data is incomplete — use Copy Crew Names to copy crews up or down to adjacent flights within a pairing as needed. Work date-wise from oldest to newest with the Display Flts window open; on a large enough screen it updates in real time as you edit, so you can verify each change immediately.
  5. Watch for redeye/overnight duty — crew data can occasionally land misaligned by one row against the correct flight in this situation. If you spot it, the fix is to move the crew data up one line and delete the resulting dangling empty line. This is an infrequent edge case, so don't be surprised if you go a long stretch without seeing it.
  6. Export to LogTen using LogTen Export or HTML Export.
For large historical logbooks, process and export one year at a time once you're comfortable with the workflow. Once a year is complete and exported to LogTen, create a new data file for the next year — leading the filename with the year (e.g. 2024 Floggy Wilco.flgy) keeps your archive sorted chronologically by name in Finder. This keeps each file manageable and maintains Floggy performance. See Section 5 for data file management tips.

Calendar Workflow

  1. Select flights in the Flt Data workspace.
  2. Navigate to the Cal – ICS or Cal – APS workspace.
  3. Select desired event types (Flt Cal, Duty Cal, Trip Cal).
  4. Press Build ICS Data or Build Events and review the preview table.
  5. Press Write ICS Files or Add Calendar to write events.

See Section 10 for full details on each calendar method.

Section 14 — Glossary

.flgy
Floggy's native data file format. Contains all your flight data, crew records, and preferences. Created and managed via the Export User Data and Import User Data buttons in the Data workspace.
.flog
Floggy's compact archive format for WebArchive parses, also referred to internally as a fixture file — Floggy can re-parse a .flog exactly as if it were the original capture. Contains just the data sections Parse (Archive or HTML) actually needs — roughly 100x smaller than the original .webarchive. Written automatically to your Documents folder each time you run Parse (Archive or HTML), for reuse or as a simple archive; you may delete or move these files manually at any time.
AppleScript
A macOS automation language that Floggy uses to write events directly into Apple Calendar without requiring you to import a file. Used in the Cal – AppleScript workspace.
Currency
In aviation, currency refers to meeting the minimum recent experience requirements to legally act as pilot in command or perform specific operations. For example, three takeoffs and landings within the preceding 90 days for passenger carrying operations. LogTen Pro tracks currency automatically when landing and approach data is complete and accurate. Floggy captures landing data from the eCrew Pilot Logbook report via Parse LogBook.
Deadhead (DH)
A flight leg where you are a passenger rather than an operating crew member, including limo transfers. Deadhead legs carry DH in the DH field (22) and flight type 1. Parse LogBook treats a leg with no block time and no PIC or co-pilot time as a deadhead.
Duty Code
A code used by eCrew to identify the type of duty assigned — for example line building, union business, or training. Floggy maps these codes to plain-language descriptions in the Data workspace.
eCrew
Your airline's crew management system — the source of all schedule, pairing, and logbook data that Floggy imports.
Base Time
Clock time at your home base (eCrew Base), as opposed to the local time at each station. The eCrew Pilot Logbook report shows all times in base time; Parse LogBook converts them to station time.
FDP
Flight Duty Period — the regulated time window during which you are legally allowed to fly. Tracked by Floggy from eCrew pairing data.
FDPS / FDPE
Flight Duty Period Start and End times. The regulated time window during which you are legally allowed to fly begins at FDPS and ends at FDPE. Floggy captures these times from eCrew pairing data and maps them to LogTen Pro fields for FDP tracking and regulatory compliance monitoring.
flightKey
A unique identifier built for each flight at LogTen export from its date, flight number, departure and arrival — for example 102620262056SBPPDX. Sent as LogTen Pro's flight_key field, so exporting the same flight again updates its LogTen entry instead of creating a duplicate.
HyperXtalk
The open-source continuation of the LiveCode platform. Supports modern Apple Silicon (ARM64 / M-series) processors. Required for running Floggy as a stack file on Apple Silicon Macs.
ICS
A universal calendar file format (.ics) that any calendar application can import. Compatible with Apple Calendar, Google Calendar, and Outlook. Think of it like a PDF but for calendar events.
LiveCode
The development platform used to build legacy versions of Floggy. Supports Intel-based Mac systems. The LiveCode Community Edition runtime is required for running legacy Floggy stack files.
LogTen Pro
The electronic logbook application that Floggy exports flight data to. Floggy supports direct export via the LogTen API as well as HTML file export for mobile devices.
Monospaced Font
A font where every character takes exactly the same width. Required for Floggy's data panels so columns line up correctly and flight data remains readable.
Pairing
A sequence of flights and duties assigned to you as a trip. Pairing details are captured in eCrew via the Pairing Details window and saved as a WebArchive for parsing by Floggy.
Part 121
Commercial airline operations conducted under FAA Part 121 regulations. Floggy captures Part 121 classification from the eCrew Pilot Logbook report.
Part 91
General aviation operations conducted under FAA Part 91 regulations. Floggy captures Part 91 classification from the eCrew Pilot Logbook report.
People
LogTen Pro's crew roster feature. Stores records for each crew member you have flown with, including name and certificate details. Floggy populates crew associations automatically via the Crew Names panel in the Data workspace. Keeping People records current ensures clean crew associations in LogTen exports.
RainMaker
A pay calculation system used by some airlines. Floggy's Calculate Rig function produces output that can be compared against RainMaker to verify trip pay.
RIG
A contract-based minimum pay guarantee per trip calculated from the ratio of trip time to flight time. Floggy's Calculate Rig function computes this value from eCrew pairing data so you can verify your pay statement against RainMaker or your airline's pay system.
Rosetta
A macOS compatibility layer that allows Intel-based applications to run on Apple Silicon Macs. May be required for legacy standalone builds of Floggy on M-series Macs.
Smart Groups
A LogTen Pro feature that allows you to create dynamic groups of logbook entries based on specific criteria. For example, a Smart Group can gather all entries containing a specific crew capacity code, allowing bulk edits across matching entries without modifying records one by one.
TAFB
Time Away From Base — the total time away from your home base airport from report time to release time. A contract-based calculation used for pay and rest purposes. LogTen Pro tracks TAFB automatically when duty start and end times are complete. Floggy captures duty times from eCrew pairing data via Parse (Archive or HTML).
TCC
Transparency, Consent, and Control — the macOS privacy permission system that manages application access to Calendar, Files, Automation, and other protected resources. Floggy requires TCC permissions to function correctly.
Training Code (TRG)
A one-letter code in field 31 of a flight record marking a training leg, taken from the letter eCrew shows in brackets on the training event — for example e for IOE, c for a line check, r for right-seat pay, f for supervised line flying. Upper case when you were the instructor, lower case when you were the trainee. Set by Parse Schedule and Parse (Archive or HTML); exported to LogTen Pro's custom note 5.
Flight Type
Field 28 of a flight record: 0 = revenue flight, 1 = deadhead, 2 = ground/non-flying duty, 3 = simulator, 6 = reserve. Sent to LogTen Pro's flight_type field.
UUID
A unique identifier assigned to each ICS calendar event. Prevents duplicate events when the same ICS file is imported more than once into a calendar application.
WebArchive
A single file (.webarchive) that Safari creates when you save a web page. It captures a complete snapshot of the page at that moment including all embedded data. The preferred format for saving eCrew pages for Floggy imports.

Section 15.1 — Tips for LogTen Pro

The following tips apply to LogTen Pro and can help you get the most out of your logbook once flight data has been imported from Floggy.

Use All Data Sources for Best Results

Floggy is designed to work with multiple eCrew data sources. Using all three sources together, in the order below (see Section 8, Recommended Order), produces the most complete logbook entries and leverages the full capabilities of LogTen Pro:

Parse Schedule

Provides trip structure, pairing numbers, and duty assignments.

Parse (Archive or HTML)

Adds leg-by-leg detail including actual times, aircraft type, tail number, crew names, FDP start and end times, and duty periods.

Parse LogBook

Run last. Adds the legal record: out/in times, tail, block, PIC/SIC capacity, who landed each leg, instructor time, and Part 121 vs Part 91 classification.

Together these sources enable LogTen Pro features including:

  • Duty period tracking
  • Flight Duty Period (FDP) tracking
  • Time Away From Base (TAFB) calculation
  • Accurate currency tracking based on actual landing data
  • Part 121 and Part 91 time separation
  • Instructor and examiner time tracking
  • Complete crew association via People records

The more complete your source data, the less manual entry is required in LogTen Pro and the more accurate your logbook currency, pay verification, and regulatory tracking will be.

Lock Completed Entries

When you are satisfied that a logbook entry is complete and accurate, lock the entry. Locking helps indicate that the information has been reviewed and finalized, and prevents accidental changes to entries you have already verified.

Learn to Use Smart Groups

Smart Groups allow you to gather entries that meet specific criteria so you can quickly review or make mass changes to qualifying entries.

Example: Create a Smart Group for entries containing "SI" and then bulk-enter SFI / Simulator Instructor time across all matching entries at once. This is a powerful feature that helps you efficiently organize and fine-tune your logbook without editing entries one by one.

Sort Entries by Column Header

Click any column header in LogTen Pro to sort your entries by that field. For example:

  • Click Departure City to sort entries alphabetically by departure airport, making it easy to scroll through and find all flights departing from PDX.
  • Click Date to return to chronological order.

Sorting is a quick way to spot missing data, verify entries, or prepare for bulk edits using Smart Groups.

Currency Tracking

LogTen Pro currency warnings are only as accurate as your landing and approach data. Since Floggy captures who landed each leg from the eCrew Pilot Logbook report, review landing data carefully before locking entries to ensure currency tracking is correct.

Approach type and count are not currently parsed from eCrew and should be entered manually in LogTen Pro after import.

People Records

Keeping your crew roster clean in LogTen Pro's People section pays off when reviewing who you flew with and for certificate and rating requirements. Floggy populates crew associations automatically — review the Crew Names panel in the Data workspace periodically to ensure records are current.

Backup

LogTen Pro stores its database locally. Enable iCloud sync in LogTen Pro settings and periodically export a CSV backup. If your Floggy data file is your source of truth, keeping both backed up gives you two independent recovery paths.

The parsing now handles edge cases in crew data, embedded training event sections, and DST-aware timezone conversion using airport-specific timezone data. The pipeline is organized into discrete numbered steps for easier debugging.

Parse (Archive or HTML) — Chrome & Firefox Support

Parse WebArchive has been renamed Parse (labeled "Parse / Archive or HTML" on the button) and now accepts three kinds of saved input from a single button: a Safari WebArchive (.webarchive), a Chrome or Firefox saved HTML page (.html, with its companion "..._files" folder), or a previously written compact .flog archive. See Section 8, Parse (Archive or HTML), for full details and usage steps for each browser.

Safari remains the recommended browser, in part because a saved page can be captured on an iPad or iPhone and mailed to your desktop. Chrome and Firefox are fully supported for users who prefer them, and work well on older Macs that can no longer run a current version of Safari. See Section 8 for the developer's full note on browser choice.

Calculate Rig — Chrome & Firefox Support

Calculate Rig now accepts the same three input types as Parse — WebArchive, Chrome/Firefox HTML, or a compact .flog archive — instead of requiring a WebArchive file specifically. See Section 8, Calculate Rig, for details.

Compact Archive Files (.flog)

Every successful Parse WebArchive run now also writes a small compact archive of the parse to your Documents folder. These files use the .flog extension, are roughly 100x smaller than the original .webarchive, and are named like your other archived files (see below).

A .flog file exists purely for your convenience — a compact record of a past parse, or for reuse if you ever need to re-run a pairing through Parse WebArchive without the original (much larger) .webarchive file still around. Floggy does not manage or clean these files up on its own; feel free to manually delete or move them as you see fit.

File Archiving

Parse Schedule, Parse LogBook and Parse (Archive or HTML) file their source material in your Documents folder under one Finder-friendly name, e.g. WILCO-1234_Schedule_2026-07-01_to_2026-07-31.csv. See Section 2, Managing Saved Files.

CSV File Format for Schedule and Logbook Reports

The eCrew Schedule report and Pilot Logbook report are now imported as .csv files rather than .txt files. Save both using the "Save as Text (.csv)" option in the eCrew export dialog.

Schedule File Parsing Improvements

Parse Schedule includes a rebuilt calendar grid date parser that uses the day-of-week column layout to anchor dates correctly across schedule formats. AIMS duty code suffixes are now separated more reliably, and flight record construction has been refactored into discrete functions.

Logbook Report Parsing Improvements

Parse LogBook has received pipeline bug fixes that improve accuracy when merging logbook records with existing parsed flight data. The merge function now correctly handles tail matching across multiple records.

Flighty Import — Year Selection & Archiving

Because a Flighty export contains your entire flight history, Parse Flighty now asks which year to import before parsing, defaulting to the most recent year found in the file — earlier versions imported every year in the export on every run. After a successful parse, Floggy also moves the file into your Documents folder and renames it using your last name and the imported year, matching the archiving behavior already used by Parse Schedule.

Training Code Support

Training codes (field 31, TRG) are now supported. Parse HTML automatically detects and extracts training event data from the Training Details section of the pairing WebArchive. Both SLF (line check) events matched by date and flight number, and IOE events matched by date and actual departure time, are supported. Training codes are also assigned by Parse Schedule based on AIMS duty type codes.

Bypass Dashboard Now Also Skips Training Events

Bypass Dashboard is meant to skip everything but the Pairing Details when you're parsing a WebArchive from a bid month other than your current one — since Dashboard, Crew Data, and Training Events on the saved page always reflect the current bid month regardless of which pairing you captured. Training Events extraction was missed when this toggle was first added, so it kept running even with Bypass Dashboard on; it is now correctly skipped along with Dashboard and Crew Data.

Add Calendar — Time Zone Support Reminder

Add Calendar (Cal – APS) now shows a confirmation dialog reminding you to check Calendar.app's Time Zone Support setting before creating events. This preference lives entirely inside Calendar.app and can't be checked or set by Floggy — see Section 10, Cal – APS, for details.

User Guide Format

This guide is now an HTML document. It can be opened in any web browser directly, or via the Help button in Floggy, which opens it in your default browser.

Data File Safety Improvements

The File Path For User Data control in the Settings workspace footer bar is now interactive. Clicking it opens a New File / Load Existing / Later prompt instead of jumping straight into a file picker:

  • New File — choose a location and start a fresh data file. If a file already exists at the location you choose, Floggy will not overwrite it — you will be told to pick Load Existing instead, or choose a different name.
  • Load Existing — opens a saved .flgy file. This never writes to disk, so it is always safe to browse with.
  • Later — dismiss the prompt. You will then be asked whether to keep your current file path or reset it.

Export User Data and any Save As action now check whether a file already exists at the destination before writing. If it does, you will be asked to confirm the overwrite rather than having it happen silently. This closes a prior failure mode where selecting an existing file — even just to look at it — could silently replace its contents with whatever was currently loaded in the stack's fields.

If you ever pick the wrong file by mistake, this confirmation step is your safety net — always read the dialog before choosing Overwrite.

Automatic backups (written on quit) are also now protected: if a backup for today already exists, the new backup is saved alongside it with a numbered suffix — (2), (3), and so on — instead of replacing the earlier one.

Confirm Before You Load

Loading a file — whether through Import User Data, the File Path For User Data control, or Floggy's own startup load — no longer replaces your data silently. Before anything is applied to the stack's fields, Floggy shows a summary of the file you are about to load:

  • Crew name and base
  • Number of flight records and crew records
  • The file's last-saved date

Review this before choosing Load. It is the fastest way to catch a wrong file — especially useful when you keep several similarly named backups (e.g. dated Floggy Back Up files) in the same folder.

Cancel at this dialog leaves everything currently in the stack's fields untouched.

Separately, Import User Data now warns you before it loads anything: if you have unsaved changes sitting in the stack's fields, you will be asked to confirm before they are replaced.

Reset User Data

Clears flight and crew data so you can start fresh — typically used when moving to a new year or bid period. Interface settings (fonts, button styles, cal list selections) are left as-is. You will be required to point at a file afterward — either Load Existing or New File — there is no Later option here, since leaving the file path pointed at the old file after clearing the data risks silently overwriting it with the now-empty fields.

Airport Data, Duty Codes, and Bid Data are left untouched — these are static reference tables, not something Reset User Data needs to touch.

Year-Filtered Export

Export User Data now supports a second export mode. Hold Option while clicking Export User Data to export a single year's worth of flight and crew data to its own standalone .flgy file, rather than your entire dataset. You will be prompted for a four-digit year; Floggy filters flight records and crew records to that year and writes them — along with your full reference tables (airports, duty codes, crew names, etc.) — to a new file you choose the location for. The result is a complete, independently loadable file scoped to one year, useful for archiving a completed year or working on a smaller subset of data. Your current working file and its file path are not affected.

HTML Export — Auto-Open

HTML Export now opens the exported file directly in your default browser after saving, instead of only saving it to disk.
